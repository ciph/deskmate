# YUME 第一版养成系统方案

状态：方案草案，尚未实施。日期：2026-10-29（Asia/Shanghai）。

第一版围绕小窝、自主活动和轻互动，建立一个每次参与约 10–60 秒、能留下可见变化的桌面生活循环。聊天、工作台、模型选择、工具执行和权限继续承担原有 Agent 职责。养成进度由本地程序维护，基础玩法不依赖模型或网络。

建议交付范围：一个 2D 小窝、五个摆放位置、十二件物品、三类自主活动、三种轻互动、三段相处阶段，以及可恢复的本地存档。下文的时间、数量和界面尺寸是首轮设计参数，原型体验后再调整。

## 2. 用户体验与首轮闭环

首次进入：右键角色 → 小窝 → 看见已有简单家具的房间 → 放好一件欢迎小物 → 选择让角色自己安排活动或指定一项活动。首次介绍使用一段仅出现一次的 60 秒短活动，结果和普通活动一样真实入档；后续采用正常时长。

再次回来：查看一张生活卡片 → 看到角色带回的小物或见闻 → 选择放进房间、收进收藏，或玩一次小寻物。关闭面板后，角色继续留在桌面，原来的聊天入口随时可用。

可见的变化包括房间摆设、物品来历、相处纪念和活动偏好。无需饥饿、清洁、掉好感、连续签到或体力消耗；关闭几天不会产生照料债务。第一版不增加货币、商店、抽奖、战斗、自由建造和多人联网。

**一次具体体验**：你把小杯子放在桌面，选择“自己安排”。稍后角色散步回来，留下“在窗边小路发现一颗弯弯的石头”的卡片，月牙石自动进入收藏。你打开小窝，把它放上展示架，再完成一个三选一寻物。下次查看月牙石，可以看到是谁、在哪次虚构活动里找到它的。

“窗边小路”是小窝故事中的地点；游戏不会扫描桌面文件、访问真实位置或打开外部应用来完成散步。

## 3. 小窝与界面入口

### 3.1 窗口方式

新增独立、按需创建的 `home` 小窗口，建议首选尺寸 400 × 460 逻辑像素，按显示器工作区收缩。首次放在角色附近；用户拖动后保留位置，开窗时校正到可见工作区。它默认不置顶，不抢占聊天或工作台输入。

入口为角色右键菜单“小窝”和设置中的“伙伴生活 → 打开小窝”。设置入口同时解决右键操作不便的可访问性问题。角色原本的单击、Enter/空格打开聊天、拖动以及现有戳动作保留。

关闭或 Esc 隐藏窗口，已创建的窗口可复用；隐藏时卸载场景动画和小游戏、释放临时监听。首次未打开时不创建 WebView、不加载场景资源。重新打开读取宿主最新快照，不能依赖旧页面内存。

### 3.2 面板组成

| 区域 | 内容与操作 |
| --- | --- |
| 顶栏 | “小窝”、当前角色头像与名称、关闭按钮；角色切换继续使用已有设置入口 |
| 场景区 | 固定视角的 2D 房间，家具底图、五个摆放位置、角色所在位置的头像小立牌 |
| 近况 | “正在翻书”“散步回来啦”等一行状态；默认显示大致时段，不常驻秒级倒计时 |
| 轻互动 | “打招呼”“玩一下”“布置小窝”三个按钮 |
| 底部抽屉 | 生活卡片、收藏、活动安排；在同一小窗口内切换 |

小窝中的角色先表现为已有头像组成的纸片立牌，随活动切换到书桌、窗边或休息处，配短暂图标和轻微过渡。桌面原角色继续用原渲染器。这是第一版的美术取舍：保证所有角色可用，同时不额外加载第二套 GLB/Three 场景。原型需要确认立牌与角色风格是否协调。

### 3.3 摆放规则

五个固定位置：窗台、桌面、展示架左、展示架右、墙面。点击位置后从兼容物品中选择，再点击确认；第一版不要求拖拽摆放。

每件物品有固定类型和兼容位置；一件物品同一时间只放一处。替换、移回收藏都不消耗物品。房间布局和收藏全局共享，切换角色后仍能看见已布置的小窝；物品来历保留发现它的角色。

摆放动作成功后立即改变房间，并显示简短反馈。保存失败保留原布局和选择，不假装已保存。

## 4. 自主活动

### 4.1 三类活动

| 活动 | 普通时长 | 小窝表现 | 结果 |
| --- | --- | --- | --- |
| 翻书 | 20 分钟 | 立牌停在书桌，短暂书本标记 | 一段读书见闻，有机会解锁该类未获得物品 |
| 散步 | 30 分钟 | 房间留下“去散步了”的标记；桌面角色仍可交互 | 一段散步见闻，有机会解锁该类未获得物品 |
| 做手工 | 40 分钟 | 桌面出现材料图标和阶段变化 | 一件小作品的故事，有机会解锁该类未获得物品 |

活动是本地生活模拟，不调用 Agent 执行文件、终端、浏览器或 Windows MCP 操作。读书也不自动读取用户文档。文本模板和确定的随机种子决定故事变体，模型不参与奖励结算。

### 4.2 自动与手动安排

用户首次进入时选择“让它自己安排”或“我来安排”，以后可以修改。未开启养成时不运行生活调度；升级用户不会突然收到养成通知。

自动安排只为当前桌面角色运行一个活动。结束后留出 10 分钟休息，再挑选下一项；从最近两次的类型、用户明确设置的偏好、各类剩余收藏中选择。三个类型都可用，不通过读取聊天猜测用户情绪或兴趣。

手动可以指定“下一次做什么”，覆盖下一次自动选择。每次最多保存一项待办，不形成长队列；当天活动额度用完后，待办留到下个生活日，不继续启动产出活动。打招呼、小游戏和布置仍可随时进行。“现在回来”取消当前尚未完成的活动，无惩罚、无奖励；已提交的完成结果保留。暂停自主活动会保存剩余时间，恢复后继续。

第一版不需要通用行为树或模型路由器；一个有限状态机和本地选择规则即可。

### 4.3 结果与节奏

- 每个生活日最多产生 3 张新活动卡片；达到上限后进行无奖励的休息展示，避免全天刷记录。生活日按系统本地时区 03:00 切换，规则与现有工作日志的日期习惯一致，但不共享其数据库。
- 每个生活日最多获得 1 件新的活动物品，全角色共用额度。初始三件物品不占额度；首次短活动占当天普通活动与物品额度。
- 在额度内，活动对应分类还有未获得物品时，必定获得其中一件；先选用户尚未拥有的物品，不做付费或稀有度抽奖。该分类已收集齐时只产生见闻，不消耗当天新物品额度。
- 完成时直接、原子地记录结果、获得物品、额度和事件；用户查看卡片只是阅读，不是领取奖励，因此不用担心忘记点击而损失产出。
- 第二、第三张卡片使用不同模板或已有收藏的后续见闻。十八条模板覆盖第一轮内容，避免一天内重复同一模板。

九件可获得物品至少需要九个不同生活日集齐；这是首轮内容长度，不宣称具备长期无限内容。收集完仍可摆放、玩互动和查看见闻，后续版本再扩展活动事件。

### 4.4 退出、休眠、切换角色

关闭小窝或隐藏桌宠时，已启用的生活进度仍由宿主管理，界面不持续动画。退出应用后仅允许正在进行的一个活动按保存的完成时间结算；再次启动时至多补结算一次，不模拟离线期间的一串活动。完成卡片计入实际结算日的额度，若该日已满则仍记录已完成状态，展示为该次活动的合并近况，不再发新奖励；不会延迟到另一日重复领取。

新一轮自动活动只能从应用实际恢复运行后的当前时刻安排。长时间离开后不积压弹窗或大量待领取任务。暂停的活动在离线时不推进。

切换角色时先结算已经到期的当前活动，再冻结尚未完成的活动和剩余时间；新角色恢复自己的暂停状态或开始新活动。所有非当前角色不并行生产。切换不取消或改写正在运行的真实 Agent 会话身份。

活动开始时保存活动 ID、内容版本、故事与物品选择所需的种子，重启不重新抽取。真正结算时在事务中按当前收藏过滤候选，防止切换角色后先前预选的物品已被另一角色获得；从同一种子和剩余候选得到稳定结果。在线时以单调时钟计经过时间；跨启动使用保存的 UTC 时间恢复。系统时钟后退不倒扣已完成进度，已提交结果不回滚；大幅前跳也只补结算当前活动。生活日额度保存最近日界水位，日期后退不重新发额度。第一版不做服务端防作弊，也不承诺抵抗用户主动修改本地存档。

## 5. 轻互动与成长

### 5.1 三种互动

| 互动 | 预计时长 | 反馈与成长作用 |
| --- | --- | --- |
| 打招呼 | 2–5 秒 | 小窝立牌回应；空闲桌面角色可播放已有兼容动作。形成一次当天相处记录 |
| 三选一寻物 | 10–20 秒 | 从三个候选物中找到线索对应的物品；答错给提示，可随时关闭，参与后形成相处记录 |
| 布置与回应 | 10–30 秒 | 摆放物品、阅读并回应一张生活卡片；物品来历与房间变化保留下来 |

寻物不要求精确点击或抢时间，支持键盘选择，降低动效后仍能完成。只用已拥有的物品和内置线索，初始三件物品足够开始。完成小游戏不生产稀有物品或提高 Agent 能力。

高频点击可以获得短反馈，但同角色每个生活日最多记一次成长；摆放同一物品反复切换不会刷进度。成长不要求三个互动都完成，第一次有效打招呼、参与小游戏或明确回应/布置任选其一即可。窗口自动打开、后台计时、聊天 token 数、工具调用次数都不计成长。

### 5.2 三段相处阶段

| 阶段 | 建议条件 | 可见变化 |
| --- | --- | --- |
| 初来乍到 | 开启小窝 | 初始三件物品、基础房间与全部活动可用 |
| 熟悉桌角 | 累计 3 个有相处记录的生活日 | 解锁房间暖光样式，出现一张相处纪念卡 |
| 住得自在 | 累计 7 个有相处记录的生活日 | 解锁另一种名牌样式与静态合照卡，由已有头像和物品组合 |

界面展示“我们一起留下的生活片段”和阶段名称；不把完成每日任务作为主要界面。日期可以不连续；阶段不会因缺席下降。第一版的个性化来源是活动偏好、布置、物品来历和相处记录，不把隐藏数值宣称为角色真实情绪。

### 5.3 角色归属

房间与收藏全局共享；相处阶段、活动偏好、当前活动和生活事件按 `packId + personaId` 区分。角色包更新不改变稳定身份，也不清空进度；卸载角色包保留其档案和物品来源，再安装可恢复。缺失头像显示名字占位。

小著三代目前有不同 persona ID，第一版默认分别记录相处档案；若产品希望把它们作为同一角色的外观，应在实施前明确这三个 ID 的固定映射，并补迁移用例，不通过名称相似度自动合并。此取舍不阻塞共用小窝和收藏的体验。

## 6. 与原 Agent 的共存规则

### 6.1 能力与入口

原有轻聊、完整工作台、模型连接、角色技能、MCP、文件操作、权限请求、取消、重试、历史与工作日志保持原职责。没有体力、心情或亲密度门槛；正在散步也能立即帮用户做事。关闭或重置养成不改变 AI 设置和任何真实会话数据。

生活逻辑不申请 Agent 工具权限，不创建后台聊天，不为了生成见闻唤醒模型。第一版不要求新增供应商、推理进程或模型接口。

### 6.2 展示优先级

物理隐藏/离场/加载错误 → 真实聊天与 Agent 活动及权限请求 → 用户正在进行的轻互动 → 自主生活展示 → 原有空闲/睡眠。

这里是展示优先级，不是改变真实任务的执行顺序。Agent 在运行时，桌面继续显示原思考、工作、成功或错误动作。生活计时可以继续，完成时只写入生活记录；不能在真实任务失败时播放养成庆祝覆盖失败反馈。用户打开小窝时可照常看收藏和布置，涉及桌宠的额外动作降为面板内反馈。

工作台、轻聊和原生 Agent 的运行状态来源并不完全相同。实施时必须覆盖三者及定时任务的真实 busy/permission 状态，不能只监听一个前端的 `pet-activity` 就声称所有任务都被保护。页面重载后先核对原生任务状态，再恢复生活展示。

真实任务结束后，显示当前生活状态；旧生活事件和过期角色的回调不能抢占新任务。生活完成也不能伪装成真实请求的 success 事件。

### 6.3 打扰控制

默认“安静”：只在小窝内显示新近况和非闪烁的小标记，不弹系统通知、不播放音效、不自动打开窗口、不把用户从输入框移走。第一版不增加主动说话气泡；以后如需要，可另做用户可选的少量提醒。

番茄钟专注期间和任务运行期间保持安静。点击角色的响应、权限确认与任务取消优先，不受小游戏、生活存档或活动调度锁的阻塞。

### 6.4 AI 与生活记忆的边界

第一版的游戏反馈使用本地模板。真实聊天继续使用现有模型和记忆；模型不会自动知道新的小窝事件，界面与宣传也不宣称已具备这种能力。

后续可单独增加“聊聊这件事”：用户选定一张卡片，再把限量、带 `game_fiction` 来源的事件附到轻聊中，经用户发送后才请求现有模型。需要保留原草稿、准确绑定会话角色，并让自动记忆/工作日志提取明确排除这些游戏事实。此桥接不是第一版基础闭环的前置条件。

任何“它去散步”“它做了纸房子”的故事都不是用户现实经历、真实任务完成证据或新工具授权。生活事件不写入现有记忆库和工作日志库；真实项目内容也不被抄进游戏日记。

## 7. 存档与状态设计

采用独立的本地 `yume-companion.db`，复用现有 rusqlite 依赖。由 Rust 宿主负责写入和事务，前端读取快照并提交受限操作。无需改造现有聊天、记忆与工作日志数据库，也不把多窗口会同时写入的成长数据放进 localStorage。

| 数据对象 | 最小内容与规则 |
| --- | --- |
| 全局小窝状态 | schema/content 版本、布局、当前身份、单调递增 revision、生活日水位与全局额度 |
| 角色生活档案 | 稳定角色键、阶段、有效相处日计数/上次记账日、明确活动偏好 |
| 活动记录 | 唯一活动 ID、所属角色、类型、开始/到期/剩余时间、种子、内容版本、running/paused/completed/cancelled 状态 |
| 拥有物品 | 物品 ID、首次来源活动、发现角色、获得时间；同物品唯一，来历不依赖可被裁剪的日记正文 |
| 生活事件 | 事件 ID、角色、模板与变量、发生/结算时间、已读状态；普通卡片每角色最多保留最近 100 条 |
| 操作回执 | 请求 ID、操作类型、结果 revision；与变更一同提交，覆盖重试、双击和多窗口重复提交 |

具体表拆分在实现时按事务需求确定；无需先搭建通用事件溯源框架。活动完成、物品新增、额度消耗、阶段解锁及通知标记必须在相应事务里完成。活动只能从未结算状态转换一次；操作回执不能仅存在于前端。

UI 命令只接受受限枚举和已存在物品 ID，例如读取快照、设置下次活动、暂停/恢复、取消活动、摆放物品、互动、已读和重置。服务端检查当前角色、修订版本、物品归属和摆放兼容性。事件通知只提示重新读取，丢失通知后可由显式打开/刷新快照恢复。

设置中保存“启用伙伴生活”“自主安排”及降低动效等少量配置；批量养成进度留在独立库。所有全局额度均跨角色共享，不能通过切换角色重复获得当日物品。

关闭功能：冻结剩余活动时长，隐藏养成入口之外的展示，保留存档；重新开启后继续。单独“重置伙伴生活”需明确说明只清空小窝、物品、生活事件与成长，用户确认后执行。新存档使用新 epoch，迟到的旧活动或窗口写入必须失效。数据库损坏时暂停养成并提供错误与恢复指引，不能悄悄清库，原 Agent 继续可用。

## 8. 调度、性能与动画

Rust 宿主维护一个生活调度器，等待最近活动期限、休息结束、下个可安排活动的生活日界，或用户设置/角色切换/恢复/退出的唤醒事件。空闲时无每秒数据库写入；没有可推进的活动时阻塞等待。系统恢复和显式读取时补核对时间，运行中可采用至多每 60 秒一次的兜底核对，不能在每次核对时无条件写库。该等待上限只用于时间核对，不承诺系统休眠期间仍按时产生 UI 事件。

倒计时只在打开的活动详情中展示并按分钟更新。小窝隐藏后停止 CSS/Canvas 动画和小游戏计时；活动继续由宿主维护。桌宠隐藏、离场与休眠继续遵循现有运行契约，不为保持生活模拟而启动 3D 渲染或鼠标跟随轮询。

阶段性目标：养成关闭或小窝从未打开时不新增 WebView、模型请求与轮询；养成启用但无近况变化时不产生持续 UI 事件。性能用相同角色、相同可见性和任务条件下的前后对照验证，不能用“未新增模型”代替 CPU、GPU、内存和唤醒测量。

## 9. 实施落点与顺序

以下为后续新增/修改位置的建议，不表示文件已经创建。

| 范围 | 计划落点 | 复用与约束 |
| --- | --- | --- |
| 领域规则、存档、调度、IPC | 新增 `src-tauri/src/companion.rs` 及其必要子模块 | 复用 rusqlite/serde/chrono/uuid，先纯规则再接运行时 |
| 小窝窗口 | 新增 `src-tauri/src/home_window.rs`、`home.html`、`src/home/` | 仿照现有工作台的按需创建与窗口去重；沿用工作区尺寸和多屏定位原则 |
| 类型与事件 | 新增 `src/lib/companion.ts` | 有界快照、revision、失败处理；与 petState 的任务事件分开 |
| 场景与内容 | `src/home/`、`public/companion/` 和对应本地内容定义 | 2D 固定摆位、既有头像、主题与语言机制；不升级角色包 schema |
| 入口与设置 | `src/pet/PetApp.tsx`、设置导航/设置模型与翻译 | 添加菜单和伙伴生活设置；不更改点击角色打开聊天 |
| 展示仲裁 | `PetApp`、角色展示 hook 与原生任务状态读取边界 | 保留原事件顺序规则；不把虚构生活作为任务事实 |
| 构建与权限 | `vite.config.ts`、Tauri 窗口/能力配置、`src-tauri/src/lib.rs` | 新入口纳入打包；home 窗口最小权限，不直接接触引擎认证或任意文件工具 |
| 验证与文档 | 邻近测试、`docs/runtime-lifecycle.md`、README、DESIGN、验收待办 | 实施后同步真实契约，方案草案不直接改成已实现声明 |

**阶段 A：确认视觉与共存。** 做固定布局的交互原型，核对 400 × 460 面板、立牌、五个摆位、现有聊天入口和任务运行时的展示。产出可点击原型与资源清单；不需要先接大模型。真实桌面窗口、不同 DPI 和三个渲染类型是此阶段的关键风险。

**阶段 B：完成一条可恢复的闭环。** 先只做散步、一个可获得物品、一个摆位和欢迎互动，连上宿主存档。完成启动、重启、离线一次结算、暂停、切换角色和重复请求验证。通过后才扩内容。

**阶段 C：补齐第一版内容。** 扩成三活动、十二物品、十八模板、五摆位、寻物、相处阶段和安静设置；实现额度、来源与存档裁剪。内容全部收集完也应有合理的继续展示。

**阶段 D：原 Agent 与原生回归。** 在聊天流式输出、工作台长任务、权限等待、取消和恢复时检查玩法；执行 Windows/macOS 对应原生窗口与性能验收，再决定是否进入候选发布。既有 B6/B7 未完成事项不因本方案消失。

可选 AI 卡片对话放在基础版本验证之后单独设计，不把它塞进阶段 B 的关键路径。日历、桌面感知、跨设备同步、自由装修和角色专属新动画也留待后续版本。

## 10. 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 未配置模型、断网进入小窝 | 能开启、互动、安排活动、得到物品和保存布局，没有推理请求 |
| 首次进入 | 一分钟左右可完成摆放与短活动，明确看见物品和来历，无强制教学长流程 |
| 布置后退出重启 | 同一房间、物品、摆放、角色档案恢复，不能多领欢迎物品 |
| 活动到期与两个窗口同时读取/重试 | 同一活动仅结算一次，物品与额度一致，通知重复不重复奖励 |
| 事务提交前后分别模拟崩溃 | 要么未完成并可重试，要么完整完成；不出现扣额度但没物品 |
| 退出两天再启动 | 只补结算原来已开始的一次，随后从当前时刻安排，不积压连续离线产出 |
| 日期跨 03:00、时区变化、时钟回拨/大幅前跳 | 同活动不重复、日额度不因回拨重置，无负进度或多日补发 |
| 暂停/关闭功能后退出 | 已暂停时间不推进；再次启用恢复，不修改 AI 配置或会话 |
| 切换角色、更新或卸载再导入角色包 | 房间与收藏仍在，相处档案不串角色；旧回调不覆盖新角色 |
| 小著三代、GLB、GIF、rig2d、头像缺失 | 小窝可用，缺失素材有明确降级；不加载第二个 3D 渲染器 |
| 点击/拖动/键盘打开聊天 | 原行为可用；轻互动没有侵占原快捷操作 |
| 轻聊流式回复、工作台长任务、权限等待、取消/失败 | 原任务可继续和中止；生活不抢输入，不伪造任务成功或覆盖错误反馈 |
| 小窝隐藏、桌宠隐藏、系统休眠恢复 | 隐藏动画/监听停止，宿主进度正确恢复，无大量补弹或后台持续渲染 |
| 十分钟连续点击、重复小游戏、摆放来回切换 | 可见反馈正常，成长和物品额度不被刷高 |
| 开启自动记忆和工作日志后玩养成 | 游戏散步/手工/读书见闻不出现在真实记忆和工作日志中 |
| 重置生活时旧窗口延迟提交 | 旧 epoch 操作失效；真实记忆、日志、历史和 Agent 仍可用 |
| 四主题、键盘导航、降低动效、125%/150% DPI、多屏边缘 | 控件可读可达，窗口不越界，摆位和任务入口不被遮住 |

自动验证重点放在纯状态转移、时间恢复、事务幂等、角色隔离与展示优先级；组件测试验证入口、布局选择和错误反馈。原生 Windows/macOS 验收覆盖窗口、焦点、DPI、休眠和资源变化。具体命令在实现阶段沿用 package.json 的 typecheck、frontend、Rust 和 build 检查，未实现阶段不运行这些检查来宣称方案通过。

## 11. 方案判断与待验证事项

建议先验证“打开小窝就能看见一件属于自己的变化”是否成立，再追求角色动作数量。第一版最关键的体验指标是首次可见成果耗时、一次日常互动耗时、用户是否主动回来看近况，以及 Agent 使用是否受干扰。这些先通过本地人工体验记录，不新增遥测采集。

需要在原型阶段验证的事项：2D 立牌与已有角色是否协调；单日一件物品、三张卡片是否合适；新窗口与聊天/工作台同时出现的遮挡；各平台隐藏后的资源开销。以上都是未验证的设计参数，不是已达成的产品效果。

本轮产物仅为方案与文档入口；尚未制作美术、原型或功能代码，也未进行游戏体验、原生窗口或性能实测。
