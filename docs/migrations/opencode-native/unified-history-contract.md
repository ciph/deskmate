# Unified conversation history contract

Current contract, reviewed 2026-10-10 for YUME 0.4.18 / OpenCode 1.18.21; host catalog SQLite schema version 2. Native execution facts remain owned by OpenCode; original legacy `history.json` owns legacy text and tagged local product replies. The catalog stores identity, organization, model preferences and cached summaries, never native messages, parts, attachment data, or tool output. The existing Agent archive still writes compatibility text projections; retiring new projections remains H1 in the [current verification backlog](../../verification-backlog.md), rather than an already completed guarantee.

This is the current entry for shared history, empty-session visibility, routing and data/rollback rules. Original receipts are retained in [the archive](../../archive/README.md); historical test counts and package paths below are dated evidence, not a new acceptance run.

## Identity and discovery

- Native identity is `(sidecarId, canonical directory, sessionId)`. The persisted catalog lives inside one application data namespace. `managed-local-v1` identifies that namespace's managed OpenCode data store; it survives process, port, credential and application restarts. Another data store must receive a different identity. Never use a process ID or a transient port as identity.
- `CatalogIdentity::key()` returns an opaque, unambiguous, length-prefixed native tuple. Legacy keys are exactly `legacy:<historyId>`. Never deduplicate, mutate or load a global history row by bare native ID alone.
- Normalize known existing directories using filesystem canonicalization at the host boundary to resolve symbolic links. The pure model then normalizes Windows drive/UNC casing, slash direction, verbatim prefix, trailing separators and dot segments. POSIX path case remains meaningful. Relative paths, control characters and parent traversal above a root are rejected. A cached canonical directory stays usable as an identity while its volume or sidecar is unavailable.
- Discovery is restricted to explicitly known canonical directories. Follow all native pages through exhaustion. `DiscoveryCandidate` rejects malformed identity, deleted session, child session and unknown directory with an explicit `ExclusionReason`; a native child is never promoted into a top-level organizer row.
- A legacy native projection coalesces only when its native association establishes the complete tuple. Preserve agent ownership/recovery metadata during coalescing. A matching bare ID in another project or data store is insufficient evidence. Ambiguous old text stays legacy; never infer missing native tool context.
- Failed discovery preserves cached summaries with `stale` or `unavailable` availability. Absence from a failed or partial page is not deletion. Tombstones exclude rows from both ordinary and archived lists regardless of remote retries.

## Metadata and wire shape

`CatalogEntry` serializes with camelCase field names:

| Field | Contract |
| --- | --- |
| identity | `{kind:"native",sidecarId,directory,sessionId}` or `{kind:"legacy",historyId}` |
| title / userTitle | Cached source title / nullable explicit user title. `displayTitle` selects userTitle first. Automatic first-turn titles must not overwrite a user title. |
| source | `light_chat`, `workbench`, `legacy`; creation provenance, not content authority |
| created / updated | Millisecond timestamps; updated is source activity, organization mutations must not fabricate a new conversation turn |
| pinned / archived | YUME organization state; archive is reversible |
| availability | `available`, `stale`, `unavailable` |
| ownership | `unowned`, `workbench`, `agent`; never derive ownership from title or source alone |
| runtime | `idle`, `running`, `unknown`; absence of runtime evidence is unknown |
| hasRecords | Optional tri-state: missing/null means unverified, true means record evidence exists, false means verified empty. This classifies visibility; confirmed unused empty entries are also eligible for the guarded cleanup below. |
| tombstone | null or `{requestedAt,remoteDeleted}`; durable suppression precedes explicit user deletion; automatic empty cleanup records suppression only after observed removal |

Host rows add `key`, `displayTitle` and computed `capabilities`. The metadata catalog schema is additive and independently versioned by its persistence owner. Never ask an older OpenCode binary to downgrade the native database.

## Empty sessions and shared entry

Opening chat, creating a context, choosing a folder/model or editing a draft does not create visible history or increase counts. Native user, attachment-only and tool messages count as records; local product replies, legacy text and Agent run evidence are also retained. Exclude verified empty entries before filtering, search, sorting and paging. An unknown entry is classified only after a successful scoped native message-existence request (`limit=1`); failed access, malformed/oversized responses, a title or an empty preview never proves emptiness. A previously populated entry stays visible when offline; activity on a verified empty entry triggers reclassification.

Keep the context and model metadata of the current composer, including hidden windows and selections still loading. The first actual message makes the row visible even while its response is pending. As authorized on 2026-10-10, unused empty sessions are deleted automatically after a 30-second creation/activity grace period, during background refresh and a 30-second maintenance sweep. Runtime must be idle, availability known, and ownership unclaimed. All Agent run evidence, linked local replies, any native message (including file/tool/user-only), children, and uncertain responses prevent deletion. Native cleanup pauses while the workbench is visible and retains its selected session when hidden; reveal/selection and deletion are serialized. Failed or superseded light-chat loads remain conservatively protected until restart.

Immediately before native deletion, the host verifies the full scope, unchanged timestamp, no children, a valid empty message response and idle native status, then rechecks metadata. Only observed remote absence produces a confirmed tombstone; a failure retains the row and the next attempt must prove emptiness again. This uses the managed sidecar API, never direct writes to its database. The pinned API has no atomic conditional-delete operation; these guards cover YUME composers and managed task launches, not an independent external writer using the same API. Legacy cleanup removes only an unchanged empty, unlinked, non-Agent record while holding its storage lock. Nonempty legacy rollback text remains intact. The [older empty-history receipt](../../archive/history/empty-conversation-history.md) records the superseded visibility-only behavior.

History list reads return the local catalog and schedule coalesced discovery in the background; events arriving during a pass request another pass. Source imports use committed legacy/index/run/association revisions, with startup and low-frequency source recovery as described below. Single-record reads use the catalog primary key, and transactions write only added, changed or removed rows. Confirmed empty content is rechecked only after activity changes or as a final deletion guard. Opening a transcript reads native scope once, then fetches status and messages concurrently; ordinary send/status checks use the metadata-only `history_catalog_access` command. Persona prompt lookup is cached for 30 seconds and invalidated on pack import/removal. Native-message content is not duplicated in the catalog.

### Committed source revisions (2026-10-24 H18a)

A warm source-import check reads revision counters without cloning or hashing whole transcripts or rereading every RunRecord. History replacement and Agent identity/active-state writes invalidate only after durable success. Unchanged prepared snapshots, failed writes, streaming part IDs, pending usage and pending finish do not invalidate the import unnecessarily. Native identity/source association changes advance a separate revision only after the catalog transaction commits. Organization, deletion receipts and tombstones remain database-owned and are read directly; workbench ownership and its six-second lease are still derived and checked live on reads and operations.

Imports are serialized. A failed import never advances its completed revision; a source generation changing during import leaves it dirty and requests another refresh. At startup, and on the next import check at least 30 seconds after a successful recovery pass, history/index files are reloaded under their writer locks and run files are reread. Malformed sources preserve the previous in-memory value and fail the pass for retry. This is demand-driven reconciliation, not a background polling or external-change latency guarantee. It does not copy native OpenCode transcripts or modify its database.

The recovery pass and changed-source import still scan complete source data. Catalog listing and generic mutations still decode the full catalog; SQL paging and targeted mutation work remain H18b/H18c. These revision changes do not change the database schema or make the complete history endpoint constant-time. Automated macOS results and outstanding native acceptance are recorded in the [backlog](../../verification-backlog.md#2026-10-24-mac-b6-h18a).

The tray's **全部对话记录** and workbench-local **Ctrl+Alt+H** both reveal the same organizer in `chat`. The shortcut ignores repeats, text composition and added Shift/Meta. `show_history_organizer` permits only `chat`/`workbench`; the host stores a pending boolean request and emits `history://open` to chat. Chat installs its listener before consuming the request on mount or event, preserving clicks before mount. Opening the organizer neither selects, clones, creates nor sends a session and does not change ownership. Row selection routes by the complete directory/session identity and shared capabilities. Build the generated bridge through the [current workbench entry](../../workbench-build.md); the [original entry contract](../../archive/migrations/opencode-native/history-entry.md) preserves the implementation receipt.

The organizer uses the existing small 420×560 and expanded 720×760 chat windows. It groups conversations, gives pinned rows precedence, keeps search/filter controls and menus within the viewport, and loads previews only for visible rows plus a small margin. Loading, failure, offline, no-result and pending-mutation states remain distinct. Composer folder changes, pending model choice and attachments are isolated by draft/session generation; late folder/model/search responses cannot overwrite a newer selection. Busy Stop and approval notices stay reachable without creating a second composer. The current visual rules live in [DESIGN.md](../../../DESIGN.md); original [organizer](../../archive/history/history-organizer-redesign-plan.md) and [composer](../../archive/chat/chat-composer-workspace-model-plan.md) plans preserve their dated receipts and unfinished native matrix.

## Data ownership and rollback

OpenCode owns its native database, logs, tool output and repository cache. YUME owns the catalog, legacy/local product text, RunRecord execution metadata, settings, memory/worklog databases and imported persona assets. RunRecord and summaries do not replace native execution facts. The legacy `native-session-index.json` reader remains a compatibility input; current identity must resolve to the full catalog tuple. Memory/worklog deletion and independent commit/receipt rules are maintained in the [memory contract](../../memory-and-worklog.md).

UI rollback and database downgrade are separate. Hiding the workbench preserves native sessions and metadata; pure legacy text remains read-only without fabricated tool parts. Never replay old text as a native prompt, overwrite current data with an old backup, or let an older sidecar write a newer database. Format conversion requires a verified isolated copy/export; when lossless conversion is unproven, retain the current database and newer entry. Tombstones, legacy bytes, local-only tags, Agent ownership and message/part deduplication remain protected. The [original ownership and rollback receipt](../../archive/migrations/opencode-native/data-and-rollback.md) retains synthetic migration hashes and isolated installation evidence; its P0 no-auth and private configuration observations describe that baseline only. Cross-version rollback remains in the [backlog](../../verification-backlog.md).

## Capability matrix

The following assumes a row without a tombstone. The host recomputes runtime/ownership before a mutation; renderer capability flags are presentation guidance, not authorization.

| Row | Read light chat | Open workbench | Send light chat | Rename | Pin | Archive/restore | Delete |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Native available, unowned, idle | yes | yes | yes unless archived | native API | local | local | confirmed + live guard |
| Native available, workbench/agent owned, idle | yes | yes | no | native API | local | local | confirmed + live guard |
| Native running or runtime unknown | yes when available | yes when available | no | when available | local | local | no |
| Native stale/unavailable | cached summary only | no | no | no | local | local | no |
| Legacy text | yes | no | no | local override | local | local | confirmed + idle guard |
| Tombstoned | no | no | no | no | no | no | retry handled internally |

**Approved archive adjustment (2026-09-24):** user-visible archive is local to YUME and does not call the native archive API or alter the workbench sidebar. Native archive timestamps are not silently imported as YUME user archive. This supersedes the original plan's native PATCH requirement. Archive remains available offline and is separate from agent recovery snapshots called “archive”.

`HistoryCapabilities` contains boolean `open`, `openWorkbench`, `send`, `rename`, `pin`, `archive`, `delete`, plus nullable `readOnlyReason`. Reasons are `deleted`, `native_unavailable`, `legacy_text_only`, `archived`, `active_task`, `runtime_unknown`, `workbench_owned`, `agent_owned`. A row may be readable while unable to send. Native cached summaries do not imply an offline transcript cache.

Explicit user-initiated permanent delete requires UI confirmation, a fresh host safety check, an atomically durable tombstone, then remote deletion. Failed remote deletion leaves the tombstone available for retry. Tombstoned native projections and delayed agent snapshots must never recreate a visible row. Original legacy bytes remain intact for rollback; the organizer hides deleted legacy rows through metadata.

## Agent record persistence and usage recovery (2026-10-22)

Agent updates compare the complete candidate `RunRecord` with the current record before serialization. Repeated unchanged snapshots and session bindings skip serialization, file sync and rename; a changed record must still persist successfully before replacing RAM state or publishing its terminal result. The pending outcome and authorization boundaries are unchanged.

The Agent archive resolves `origin_run_id` through one `RunStore::get` instead of loading every archived run. This read validates the requested ID, requires an ordinary non-symlink file and verifies that the decoded record has the same run ID. Startup recovery still loads the run archive; other history discovery paths are not made constant-time by this change. Compatibility text projection remains as described above.

Completed assistant-message usage is taken directly from the collected native snapshot when all required fields are valid. Missing or invalid observations, unknown providers and local accounting failures retain message IDs in the run's durable `pending_usage_message_ids` field. The marker is persisted before publishing a terminal run and remains on terminal records across restart; older records default to an empty list. Startup restores pending work from all loaded runs, independently of the recent-runs UI page limit.

A separate worker rotates through pending runs with a 32-run execution window and one HTTP lookup at a time. Failed rounds back off from five seconds to a maximum of five minutes; older pending runs cannot permanently exclude later runs. HTTP runs outside the Agent operation and sidecar-generation locks. Before applying an observation, the worker rechecks the engine generation and the complete run/session/canonical-workspace/creation identity against the target record. A late response cannot replace a newer run or change its outcome. Only successful idempotent accounting, including the ledger temporary-file sync and atomic rename, permits clearing the durable marker; missing messages or incomplete replies remain pending. Shutdown leaves durable pending work for the next startup. The usage ledger rejects conflicting provider/model/creation identities instead of overwriting them. These are local usage recovery rules, not a guarantee that an unavailable provider or deleted native message will eventually supply usage. The worker still checks in-memory retry state once per second; backoff limits HTTP retries, not every host wakeup.

## Local product replies and scoped recovery (implementation clarification)

New deterministic local replies use `HistoryMessage.localOnly = true`. Their auxiliary record remains in the existing `history.json`, with `localLink` carrying the complete native identity and a `local_<SHA-256(composite key)>` storage ID. It contains only local product text, never a copy of native messages, parts or tool state. Import excludes these auxiliary records from organizer rows. Reads merge tagged local text by the exact composite identity; writes cannot replace another project's note or the original untagged legacy record. The renderer labels these local replies explicitly. No native API replay or direct native database mutation is used.

Old untagged compatibility text is only exposed as a text-only/read-only fallback after the scoped native transcript is verified empty. Once actual native content exists, it remains the native authority; untagged projection text is never replayed as native messages. Original legacy data remains stored for rollback.

Native agent details are serialized alongside catalog load results, selected using native directory plus session ID. A legacy recovery detail requires its trusted origin run. Bare-ID collision cannot borrow another project's recovery status, scheduled provenance, transcript or catalog organization.

## Chat composer model preference (2026-09-27)

The host catalog SQLite schema advances from `user_version = 1` to `2` without altering native transcript ownership. `model_selections(key, selection)` stores an optional `inherit` or explicit `{ configuredProviderId, sidecarId, modelId }` choice by the complete catalog key. Missing rows, including all pre-migration conversations, mean `inherit`. Refresh, rename, pin, archive, and native metadata rediscovery preserve the row without changing message timestamps; deletion removes the preference when the catalog entry is removed. A bare native session ID is never used to find or migrate a preference.

The chat window reads and writes this preference through authenticated host commands. An explicit choice is accepted only for an available, idle native entry outside workbench ownership and only if the active configured provider, its runtime sidecar ID, and the exact model are present in the provider's currently verified URL/key-bound catalog. The host resolves `inherit` from the configured default pair only when that pair is present in the same verified catalog. Invalid or stale choices block a new request rather than falling back to another model. No key, URL credential, or fingerprint is stored in the selection row.

The ordinary chat resolves the choice before `prompt_async` and sends the resulting `{ providerID, modelID }`. Agent start resolves the same choice after scoped continuation checks, verifies the renderer's expected pair, and copies it into the run's `StartSettings` before creating or continuing the native session. The first Agent request and its later tool turns use that run snapshot. A new Agent session binds its choice to the complete native identity after host history registration; existing continuations keep their original directory. Unbound composer drafts carry a pending choice only until a native identity exists. Scheduled tasks continue to use their own settings snapshot.

`recent_workspaces(directory, selected_at)` is separate UI metadata in the same database. It records only canonical directories explicitly chosen through the chat folder control, up to five most recent results. It does not import discovered directories or the built-in light-chat workspace as recent folder choices.

## On-demand organizer previews (2026-09-27)

`history_catalog_previews(keys)` accepts at most 12 complete catalog keys from the chat or workbench window. The host resolves each key through the catalog, rejects tombstones and unavailable native records, and verifies the requested native session still belongs to its catalog directory before reading content. It returns a result per key with `ready`, `empty`, or `unavailable` status. A ready result carries at most 160 Unicode characters of the latest user/assistant text, its role and message time, and a `localOnly` marker for a linked local reply. System, reasoning, tool and binary parts are excluded. The catalog and `history.json` never receive native preview text.

The pinned OpenCode sidecar's recent-message endpoint is read in pages of eight, at most two pages per preview. Each response is capped at 8 MiB and two seconds; session verification is capped at 64 KiB and two seconds. A bounded tail with no text is **not** evidence that the native transcript is empty, so it cannot activate old untagged compatibility text. The host allows at most two concurrent preview reads and stops starting new reads four seconds into a batch, leaving up to six seconds for the final read. It keeps at most 200 cached entries / 512 KiB, with 30-second success and five-second failure lifetimes. Native refresh, local reply saves and deletion invalidate affected cached results. The renderer requests only visible rows and a small scroll margin and discards responses from an obsolete list generation.

## Staged compatibility projection and chat presentation (2026-10-22 B5)

Agent snapshot collection is single-flight through snapshot reads and compatibility projection preparation. A competing collection skips without completing a durable pending recovery. Projection merging, serialization and temporary-file sync run outside the Agent operation lock. Before committing, the collector rechecks the complete RunRecord and sidecar generation. The history commit also holds the actual workbench ownership lease guard, checks the unchanged whole-file history baseline and native/legacy tombstones, and atomically replaces the file before publishing RAM. Ownership or catalog contention fails immediately instead of waiting under the control lock. A superseded or failed compatibility archive remains best-effort; native transcript authority and critical run durability are preserved. Terminal archive failure does not promise an automatic projection retry.

This removes projection preparation from the control lock, not all work from the lock. Whole-history clone/comparison remains O(N); atomic rename and critical RunRecord/usage persistence still serialize. Existing cancel/settlement network paths are not a guarantee of zero network wait. Synthetic control-acquisition measurements do not establish native Stop latency.

Light-chat presentation publishes each message's first nonempty text immediately, then coalesces full part snapshots in a 33 ms window. Ordered text parts are retained separately and joined by native message identity; restored native parts seed the same buffer. Terminal metadata, idle/error, tool transitions and confirmed Stop flush accepted current-generation content. New requests, session changes and unmount clear pending timers; late Stop confirmation is fenced by session, view generation and request. Fixed local persona reply timing remains unchanged.

Unchanged message objects and memoized message-row props remain stable. Worklog receipts are indexed by message ID for each operations revision; persona/avatar updates still invalidate their sources. All history rows remain mounted, and the active Markdown parser and link security rules are retained. Aggregate React commits and stable historical DOM nodes do not by themselves count individual row renders or prove native input latency.

## Event-driven Agent refresh (2026-10-22 B5)

The existing authenticated permission event worker consumes the pinned OpenCode 1.18.21 global event stream. Events only invalidate one active run's scoped cache; they do not authorize actions or publish execution facts. Directory, session, run and actual sidecar generation must match. Duplicate message IDs are coalesced; up to 16 dirty messages use the singular authoritative message GET, while overflow/removal, disposal, reconnection and terminal candidates require a full snapshot. A full reconcile every 30 seconds compensates for lost events; there is no reliable replay or immediate sequence-gap detection guarantee. No active run means no collector message HTTP requests, although the shared SSE connection and independent permission/usage work remain.

Singular message responses require complete message/part identities and mandatory structures before replacing cached facts; malformed or missing results fall back to a full snapshot. Pending finish and startup recovery use full snapshots. Permission and tool deadlines still receive one-second supervision; any potentially destructive idle/timeout decision based on cached or partial facts first confirms the full native snapshot outside the operation lock. Only a result actually applied to the unchanged run may update the cache and acknowledge dirty IDs. A safe skip leaves them pending, including concurrent usage-record changes.

Permission fallback from the global stream is keyed by canonical directory, session and request, fenced by actual sidecar generation and connection state. Unscoped legacy fallback is restricted to the managed default workspace; inability to verify that scope fails closed. Replies remove matching pending requests and prevent late duplicate asks from reviving them. Bounded caches, oversized/malformed frames and disconnects invalidate state and reconcile rather than granting permission. Ordinary stream failure is recoverable and does not make application startup fatal.
