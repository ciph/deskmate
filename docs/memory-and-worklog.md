# 记忆与工作日志：当前契约

核对日期：2026-10-25（M19a 记忆到期索引）；文件桥与调度等待行为沿用 2026-10-22，其余契约沿用 2026-09-30 核对。实际实现和已执行验证见[自动处理验收记录](automatic-memory-verification.md)及[M19a 验收记录](verification-backlog.md#2026-10-25-mac-b6-m19a)；真实模型语义的未验项见[当前验收与待办](verification-backlog.md)。原设计保存在[历史施工方案](archive/memory/automatic-memory-construction-plan.md)。

## 自动处理与开关

宿主在新可信回合登记后，通过持久队列提取值得延续的事实和明确的工作信息。轻聊和工作台进入同一登记/处理链路，内部提取、报告及子会话排除。消息区不常驻“记住这件事”“保存到工作日志”“安排周报”按钮；显式工具操作仍返回真实结果。

新安装默认开启自动记忆和自动日志。已有明确关闭的自动记忆值保留。自动提取、允许 AI 使用记忆和自动日志是独立设置；改变开关使对应分支的在途结果失效，重新开启不回扫关闭期间的全部旧聊天。关闭自动记忆后，已有记忆是否用于回复仍由“允许 AI 使用记忆”决定。关闭记忆使用时停止记忆注入及相应自动提取，显式本地管理仍可用。

| 记忆自动处理有效 | 自动日志 | 行为 |
| --- | --- | --- |
| 开 | 开 | 同次受限提取分别更新记忆和日志；各库独立提交与恢复 |
| 开 | 关 | 仅更新记忆，不创建工作日志 |
| 关 | 开 | 仅整理明确工作信息，不重建记忆 |
| 关 | 关 | 无自动提取或归档；已有资料可按各自读取和显式查询规则使用 |

## 显式日志工具的可信回合

显式日志工具独立于自动提取开关。轻聊只能由聊天窗口登记当前工作目录与用户回合；工作台经宿主已验证的目录、会话和本次引擎启动登记待验证回合。工作台登记时不授予操作权限，工具执行前从受管引擎核对实际用户原文；助手、工具输出、synthetic/ignored 文本不能代替用户授权。

文件桥只在宿主内存中持有受管引擎认证，使用规范化目录和精确消息 ID 回查用户父消息及工具 call ID。重启使旧登记和请求失效；同回合重放不重置失败查询状态，撤销或过期回合不能因重复登记恢复授权。日志仍按既有全局管理语义查询，目录约束的是授权来源，未给旧条目添加新的目录过滤。

文件桥监听当前引擎启动目录中原子发布的 request；通知只唤醒单个消费者，不代替文件类型、目录、认证与授权校验。请求和回执继续通过临时文件写入后 rename 发布，回执只在真实提交或明确拒绝后生成。重复通知合并为一个待处理标记；自身临时文件、回执和请求清理事件不触发循环扫描。

空闲时按单调时钟每 10 秒补扫文件、回收过期文件与登记，并重新挂载目录监听，补偿通知丢失、监听失败或目录替换。引擎重启（包括失败重启）立即唤醒并切换本次启动目录；退出唤醒等待线程。10 秒是空闲补扫间隔，在途 HTTP 和串行请求处理另有耗时；工具原有 15 秒等待后的结果未知/pending 语义保留。执行时仍严格检查 30 分钟授权期限，不因回收降频延长权限，也不清除本次启动的撤销墓碑。

## 来源、归属与证据

用户明确自述的称呼、稳定偏好、决定和持续事项可成为记忆来源；明确工作计划、进展、成果和阻塞可进入工作日志。引用、附件正文、假设、助手建议及助手自行推断不能单独当作用户事实或完成证据。凭据拒存；敏感信息在自动路径跳过，显式保存继续经过本地政策和必要确认。

记忆支持 global/persona 可见范围；事项和来源另绑定实际项目目录与完整 catalog 身份。切换角色或工作目录不得借用另一作用域的来源。原生用户回合和受管任务必须核对消息及运行事实；Agent 自动日志目前只接受已完成运行中成功的 write/edit 文件操作，不能依据 shell 输出、apply_patch 或模型一句“完成”自动推断成果。

工作日志使用本地 03:00 切换的业务日；相对日期按来源发送时间和时区解释，明确日期优先。同源重放和精确同日工作有幂等保护。自然语言同义更正/去重依赖模型匹配既有目标；语义正确率仍需真实模型验收。

## 存储、关联与恢复

OpenCode 拥有原生聊天、消息、part 和工具事实。YUME 的 `deskmate-memory.db` 保存记忆与事项，`yume-worklog.db` 保存条目、报告、修订和调度；两库分别拥有事务、来源、删除屏障和回执，不提供跨库原子事务。来源登记和重试状态由宿主持久队列管理，失败不阻止当前聊天/Agent 继续。

记忆和日志只在各分支真实提交后报告成功。部分成功时重试未确认分支，不重复已成功的操作。提取使用来源回合的模型，在内部禁用工具的会话中完成；内部会话清理失败可以恢复，不将其再次登记为用户来源。

事项引用有效记忆和修订；归档成功的详细工作通过真实日志条目 ID/revision 关联。日志更正/删除使关联视图失效，独立偏好或目标不因此全部删除。手动更正优先于较早来源的自动提议。

### 到期索引（2026-10-25 M19a）

本地 B6 源码将记忆库 schema 从 2 升至 3，独立迁移 `003_active_expiry.sql` 仅增加 `memories(expires_at)` 部分索引，谓词为 `status='active' AND expires_at IS NOT NULL`。旧 `001`/`002` 迁移不修改；记忆、FTS、来源、事项、任务和日志关联均不重写。索引及版本在既有 IMMEDIATE 迁移事务中提交，失败保留旧 schema 与已提交 WAL；未来版本继续拒绝。旧版记忆库门禁拒绝 schema 3，不通过修改版本号降级或用旧备份覆盖新增数据。

到期行为保持原样：现有写入、列表、导出和检索路径仍在原事务中调用 `expire_due`，全局更新 active 且已到期的记忆，并清理已到期的 pending 候选。角色筛选不缩小全局到期维护范围；更新后的 FTS 可见性和删除隐私规则保留。时间仍按已有 RFC 3339 字符串的 TEXT 比较处理，包括原有偏移量和小数表示语义；本批不加入时间规范化或更换比较规则。

索引减少到期候选定位的全表扫描，不消除实际到期数量、FTS 触发器或事务锁的工作量。读取实时过滤与独立物化维护属于 M19b，FTS 精确维护属于 M19c，均尚未实施。合成库验证不代表日常用户库已迁移或原生平台验收已完成。

## 回复上下文与管理

两种聊天入口每轮获取当前记忆；工作台经带鉴权的本地 bridge 获取，避免启动时静态正文快照。轻聊逐轮 system 参数仍保留，插件按块去重。基础记忆检索有最多 8 条/1,200 字符的预算；待处理来源只能提供受限的近期用户原句补充，不能当作已保存记忆。完整历史不进入这一上下文。记忆使用关闭后不注入这些内容。

设置页可查看、更正、删除和导出记忆，并检查自动处理的失败状态、重试失败项。工作日志页管理条目、报告和调度。提取仍处理中或查询失败时不能回答“已经记住 / 没有记录”。

## 后台报告调度

调度器在启动、收到已提交的日志变更事件和宿主恢复通知后检查工作；下一次等待取启用计划的 `next_due_at`、已排队运行、重试时间及未结束租约中最近的期限，包含重试次数耗尽后仍需收尾的租约。通知合并为一个待处理标记；每次执行完成后继续领取排队工作。配置、手动任务和文件桥提交使用同一变更通知路径。

空闲等待最长 60 秒，然后重新核对数据库、墙钟与本地时区，补偿通知丢失、外部写入及时间变更；睡眠后的补漏继续使用原来的 `latest_due` 和 occurrence 唯一键。不变的 `next_due_at` 不执行 UPDATE，入队、领取、租约和报告发布仍保留原事务及 attempt 栅栏，因此空闲不等于完全没有 SQL 或事务。到期但暂不能领取（例如组件安装占用）的工作退让 1 秒；数据库或日期错误退让 60 秒。

退出会唤醒空闲线程；运行中的模型取消仍遵循既有 HTTP/heartbeat 检查。60 秒是兜底检查的等待上限，不包含当前执行、数据库等待或系统休眠，不承诺报告完成时限。文件通知和调度回归不替代 Windows/macOS 原生恢复、真实模型及整机功耗验收，未验事项保留在[当前验收与待办](verification-backlog.md)。

## 删除与报告边界

忘记记忆删除其正文、来源及检索内容，使旧来源、在途提取和重试不能重新写回；它不声称同时删除原始聊天。删除会话可以按现有选择清理来源记忆，已经归档的工作条目和报告不因聊天删除一并消失。

删除/更正工作条目使依赖报告标记为 stale/source_deleted；报告正文是独立归档产物，不自动重写。明确选择删除关联报告时按现有 `deleteLinkedReports` 语义处理报告、快照及应用管理副本，包含其他工作的报告不能因模糊指代整份删除。导出文件和服务商/sidecar 日志不随本地条目删除而自动抹除。

忘掉工作相关记忆同时阻止保留日志经普通召回或事项重建恢复已忘内容；明确查询保留日志仍可读，查询本身不是重新记忆的授权。明确要求“所有地方删除”时才协调两个领域，目标不清楚时核对所指对象。

自动日志不创建提醒、周报调度、报告生成或发送。创建这些动作仍需要明确操作意图；记住“周五交周报”只是一条背景事实。后台报告使用独立会话，重新生成的候选保留人工修改，空素材范围不发模型请求。

## 删除快照的集中处理（2026-10-22 B5）

每次删除事务一次加载报告版本与运行记录的来源清单/快照，并结合 report_sources 建立本轮临时反向关系，计算来源及派生报告的传递闭包。独立快照、缺失关系行、重复引用和深层派生仍参与擦除；没有增加持久索引或数据库迁移。过滤前后未变化的版本不 UPDATE，相关快照只处理一次。报告正文仍按用户的保留/删除选择处理，保留报告标记 stale/source_deleted。

实际删除报告时，同种类及同一完整周期的既有 queued/running/retry_wait 再生成任务也在事务中取消，即使其快照只有原始条目，不含被删除的报告版本。取消使迟到发布及续租失败；删除后新的显式生成仍允许。数据库失败整体回滚。运行记录中的独立来源快照同样擦除，不以报告关联表完整为前提。

该优化减少重复全库解码与无关行写入，仍需读取全部存储快照；内存随快照与引用总量增长。SQL 外键删除成本另计，不能声称整个事务严格线性或无锁等待。运行取消立即撤销发布资格，真实模型请求仍通过既有 heartbeat 检查感知，不能据此声称 HTTP 即时中止。合成 SQLite 操作计数不等于生产磁盘耗时或原生取消时延。
