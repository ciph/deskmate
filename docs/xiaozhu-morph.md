# 百变小著：YUME 原生接入

2026-11-01，基于本机 YUME 0.4.21 工作树实现，同日整合进 main（0.4.24 基础，未随公开版本发布）。角色 ID 为 `xiaozhu-morph`，作为小著内置包的第四个角色（内置包 1.3.0）；原来三代角色和默认选择保留。形状来自已确认的 `xiaozhu-playground-v0.1-20261101`，不是重新绘制的替代形象。

## 已确认的设定（修改前需用户同意）

同一角色的四种形态：团子轻跳回弹、枕头慵懒柔软（拎起时边角下垂）、年糕黏软拉伸小步、幽灵轻盈漂浮缓缓飘回。奶白柔软身体、黑色实心像素墨镜（6×6 单位一格、26×8 格、镜框左右对称、两个同向单格高光）和橘粉腮红保留。只有墨镜用 `crispEdges`；身体拉伸时墨镜与腮红不变形，情绪由嘴和眉表现。不改成透明镜片、普通圆框或全身像素风，不重新设计四种轮廓。

## 入口和操作

设置 → 桌宠 → 小著 → 百变小著。

| 操作 | 效果 |
| --- | --- |
| 单击 | 戳一下；睡着时叫醒 |
| 拖动后松手 | 原生窗口跟随鼠标；松手落下并软弹回稳，幽灵缓缓飘回 |
| 双击 / Enter | 打开或收起聊天 |
| 右键 | 团子、枕头、年糕、幽灵；散步、睡觉/叫醒、自己活动；聊天与原有设置入口 |
| 聚焦后空格 / 1–4 | 戳一下 / 切换四种形态 |

团子轻跳、枕头慢挪、年糕小步、幽灵漂浮。四种身体共享轮廓拓扑并在 0.8 秒内插值，连续切换从当前轮廓接续。像素眼镜和腮红使用同一组 SVG 节点，只平移，不随身体拉伸；眼镜组另按实际设备像素吸附格宽和原点，非整数系统缩放下格子不逐帧跳动。拎起、落地、呼吸、犯困和伸懒腰的弹性各自不同。

首次空闲约 22 秒散步，后续活动有间隔；空闲约 60 秒睡着。单击、拖动或菜单操作重置空闲计时。关闭“自己活动”后保留手动操作。当前形态和自动活动偏好保存在当前 WebView 的本地存储；不保存瞬时速度或动作。

## 与宿主协作

- `MorphPetView` 绘制程序化 SVG；不用 GLB，也不下载新模型。动画目标 60 fps，保留帧截止时间余数，隐藏后取消 RAF。
- 身体轮廓更新鼠标命中多边形，周围透明区域沿用 YUME 鼠标穿透；原生拖动期间沿用现有锁和物理按键释放检查。
- 只有行走、下落等位移写入原生窗口位置。工作区、任务栏边界、物理坐标和 DPI 在 `desktopMotion` 里换算；窗口写入单飞，移动/尺寸/DPI 变化刷新几何，卸载后丢弃迟到读取。拖动速度来自连续原生位置；超过 0.12 s 无新位置即视为手已停，松手时垂直落下。
- 聊天打开时暂停自动活动并停止正在进行的散步，避免带着聊天窗口移动。显式散步仍可执行。聊天关闭后重新计时。查询前安装事件监听，迟到查询不能覆盖新显示状态。
- AI 思考、执行和回复沿用真实活动状态，显示状态标记并暂停自动活动；不会用玩耍动画冒充任务完成。
- 小著人格、头像、技能及 NCM 授权随角色一起接入；技能仍需明确声明，近似名称不能获得授权。

## 验证与交付边界

### 实机手感修复版（2026-11-01）

本轮首次在 Windows 原生预览上直接实测：GDI 截屏分析窗口像素，`SetCursorPos`/`mouse_event` 发出真实系统鼠标输入，按窗口句柄读取原生位置。测试机为 3 台显示器、系统缩放 125%（含一台负坐标竖屏）、60 Hz。视觉模型在本机不可用，像素判定全部用确定性计数，不靠截图描述。

实测发现两个可复现问题并做最小修复：

- **125% 下墨镜格子抖动。** v3 中 6×6 单位的格子落在非整数设备像素上，`crispEdges` 逐帧取整不同：80 帧采样里镜框高在 46/47 px 间跳、高光在 6×6 与 6×5 间跳，呼吸时可见闪烁。新增 `pixelSnap.ts`：墨镜组单独附加变换，格宽取整到整数设备像素，原点吸附到设备网格（偏移 ≤ 半个设备像素）；嘴、眉、腮红沿用原平滑位移。SVG 盒子只在 resize/DPI 变化时测量，变换字符串不变时不写 DOM。修复后原生 120+ 帧全部为 144×48 px、两个高光恒为 6×6、位置左右对称，跨到另一台显示器后不变。墨镜图稿、网格和 `MorphSignature` 共享方式不变。
- **停手再松开仍被甩出。** 原生拖动只在鼠标移动时报告位置，速度停留在最后一次移动值，按住静止 0.3 s 后松手仍横向滑出 73 px。现在拖动中超过 0.12 s（大于 40 ms 松手轮询加 IPC）没有新位置样本即视为手已停，速度归零；仍在移动时松手保留速度。实测静止松手横向 0 px 垂直落下，带速度甩出横向滑行 255 px。

原生实测结果（v4，均为真实系统输入）：

- 帧节奏：空闲和散步时窗口像素每秒变化 59.5–60.0 次，帧间隔 p50 16.7 ms、p90 ≈19 ms、p99 ≈20 ms；个别单次最大 42–52 ms（截屏同时运行，未区分是否为采样干扰）。修复前后均为 60 fps 级，未退化。
- 透明区域命中：身体上 `WindowFromPoint` 命中宠物窗口，周围透明处落到下方窗口（扩展样式含 `WS_EX_TRANSPARENT`）。
- 单击：身体像素面积 0.2 s 内压扁约 1.7% 后回弹，约 2 s 恢复，确认为戳碰。
- 拖放：窗口跟手，松手后约 1.7 s 落到工作区底部；从主屏拖到右侧副屏、再拖到左侧负坐标竖屏都落在对应工作区内。
- 右键：出现原生菜单，Esc 关闭。

验证命令：Morph 专项 4 个文件 52 项（新增像素吸附 21、静止松手 1、视图吸附 1）；共享交互/PetApp/角色目录 28 项；`bun run typecheck`；`bun run test:frontend` 175/175 文件通过；Rust `pet_geometry` 14 项与 `ncm` 26 项；React Doctor 变更范围 98/100 无问题；Windows 原生 debug 构建（原有 19 条 Rust 警告）。

### 动作改进版（2026-11-01）

根据试玩反馈，从 30 fps 上限改为 60 fps 目标；戳碰加大挤压、回弹和闪避，拎起时的基础拉长为团子约 34%、枕头 30%、年糕 19%、幽灵 24%，垂直速度另外增加少量拉长。身体侧向拖后、枕头边角下垂及落地挤压也增强。新增随动作淡入淡出的张嘴、挑眉表情，四形态嘴形略有差别；眼镜与腮红节点不变。

修复松手重新读取几何时把速度覆盖为零的问题；速度来自连续原生窗口位置，不混入身体动画偏移。原生拖动中出现 WebView blur/pointercancel 时，由已有物理按键轮询继续管理松手；普通点击、菜单、隐藏与卸载的取消逻辑保留。

本次通过：引擎 19、视图 6、桌面物理 4、共享交互 12、PetApp 加载 12 项，类型检查和前端/Windows 原生构建。60/120/144 Hz 的确定性 5 秒时钟均绘制 300–301 次并推进 5 秒；这是调度验证，不是原生实际呈现 FPS。1200 个动作时刻的 SVG 曲线采样落在可见画布内，外部 `motion-review.png` 对照图已检查。React Doctor 93/100，仅保留此前的组件长度提示。
